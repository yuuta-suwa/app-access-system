## C. 設計上の判断・既知の限界（要確認）

1. **事前招待の自動 active 化**：Google が検証したメール一致のみで active＋指定分類にする。招待メールの誤入力リスクがあるため、運用で不要なら招待機能を使わない、または招待時も pending のまま分類のみ予約する方式に変更可能。
2. **権限変更の反映タイミング**：API は即時に拒否。表示中の画面は「画面復帰・フォーカス・5 分ごと」の再確認で作り直す（Realtime による即時プッシュは未実装）。
3. **停止時のセッション**：停止すると全データ取得は拒否されるが、Supabase Auth のセッション自体は有効期限まで残る（画面は停止画面）。即時失効が必要なら Auth の Ban/セッション削除を併用（Secret key が必要なため、管理画面からは未実装。サーバー側 Edge Function 化は今後の検討）。
4. **PostgREST 応答に Cache-Control が付かない**：クライアントは `no-store` で取得し、メモリのみに保持。CDN/プロキシを挟む場合は実環境で確認。
5. **CSP の connect-src** は `https://*.supabase.co` 前提。Supabase カスタムドメイン利用時は `vercel.json` の修正が必要。
6. **SELF の並び替え**は上下ボタン方式（ドラッグ＆ドロップ未実装）。端末同期は保存時・再読み込み時（リアルタイム同期は未実装）。
7. **アプリ単位の追加 ACL** は未実装（仕様書どおり将来検討）。機密性の異なるアプリは掲載分類を限定して運用。
8. **管理者のアプリ編集時の last_verified_at**：申請承認時は承認日を自動設定。URL の死活監視は未実装。
9. **Google Sheets 連携（エクスポート/インポート）** は未実装（仕様書上「必要なら」）。
10. DB 運営権限を持つ者は技術的に全データにアクセス可能（仕様書 4.3/10 章のとおり。追加暗号化は別設計）。
11. 依存パッケージ：2026-11-10 時点で `npm audit` 0 件（react-router-dom を 7.18 系、vite 8・vitest 5 へ更新済み）。本番前に再実施すること。
